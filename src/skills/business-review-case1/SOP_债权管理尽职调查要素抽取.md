# 债权管理服务项目尽职调查报告 · 要素抽取标准作业规程（SOP）

**版本**：case1-v1  
**适用对象**：智能体（Agent）  
**训练样本来源**：`1002-关于对成都成宇为债务人的不高于3.2亿元债权提供债权管理服务项目尽职调查报告【1015清洁】-批注版(1).docx` 及其批注索引 `docx_comments_index.json`

---

## 一、适用范围与目标

### 1.1 适用范围

本 SOP 适用于同类型的 **债权管理服务项目尽职调查报告**（以下简称「尽调报告」）Word 文档（`.docx`），包括但不限于：

- 标题或正文出现「债权管理」「债权投资」「债权服务」「尽职调查」等表述；
- 正文以 **交易结构、增信、监管、违约处置、还款来源、SPV/信托安排** 等条款性描述为主，而非纯财务分析或市场可研。

文档可以 **带批注**（业务专家已标注要素口径）或 **无批注**（仅依赖本 SOP 规则库）。

### 1.2 抽取目标

对文档中 **11 个核心业务要素**，分别抽取其在 **本文中的实际情况**（以下简称「情况」），并给出可复核的证据链。

每个要素的最终产出字段：

| 字段 | 说明 |
|------|------|
| `element_name` | 要素标准名称（与本文 §四 清单一致，不得改写） |
| `situation` | 自然语言归纳的「情况」：本文采用了什么安排、数值/机制是什么、明确不存在什么 |
| `evidence` | 证据数组，每条含 `source_file`、`locator`、`quote`（≤300 字） |
| `confidence` | `high` / `medium` / `low`：依据充分程度 |
| `gaps` | 材料缺口或未决事项数组；无缺口则为 `[]` |
| `logic_trace` | 判定过程摘要：锚点如何命中、扩读范围、口径依据（有批注时引用 comment id） |

### 1.3 非目标（禁止行为）

- **禁止** 仅输出关键词列表或「命中/未命中」而不写 `situation`。
- **禁止** 用 PPT/可研报告中的市场数据 **替代** 交易结构、增信、违约、监管类要素的主依据。
- **禁止** 在正文无依据时编造数值、倍数、主体名称。
- **禁止** 将不同要素混写为一条（如把「监管方案」写入「增信措施」），除非在 `logic_trace` 中说明交叉引用关系。

### 1.4 最终交付形态

智能体完成抽取后，输出 **单一 JSON 对象**（结构见 §六），或按调用方要求写入 `outputs/elements_extracted.json`。本 SOP 不要求同步填写 xlsx 信息收集表；填表为下游可选步骤。

## 二、术语与批注解析规范

### 2.1 核心术语

| 术语 | 定义 |
|------|------|
| **要素** | 业务审查需结构化回答的指标项，共 11 个（见 §四） |
| **情况** | 该要素在 **当前项目尽调报告** 中的具体安排与事实，非行业通用定义 |
| **锚点（anchor）** | 用于在正文中定位相关内容的标题片段、编号小节或关键句；通常不是完整条款 |
| **扩读** | 以锚点为入口，向上下或同级条目扩展阅读，直至覆盖完整证据块 |
| **口径** | 业务专家对该要素「应如何理解、如何判定」的规则，批注中冒号后的说明即为口径 |
| **负向证据** | 全文检索后确认 **未见** 某类安排（如「未有还款承诺函」），须在 `situation` 中明示 |

### 2.2 批注文本解析规则

批注 `comment` 字段常见三种形态，解析方式如下：

**形态 A — 标准：`要素名：情况摘要`**

```
风险隔离措施：设立了财产权信托计划
```

- 冒号前 → `element_name`（与 §四 清单匹配，允许括号层级变体如「风险隔离措施（SPV层面）」）
- 冒号后 → 口径提示 + 情况方向，**不能**直接照抄为 `situation`；须结合正文扩读后归纳

**形态 B — 仅要素名（无冒号后情况）**

```
SPV的分配顺序和清偿顺序
```

- 要素名即 `element_name`
- `situation` **完全依赖** 锚点扩读后的正文归纳

**形态 C — 范围/元指导（非独立要素）**

```
整体都可以作为违约处置退出方式的描述内容
```

- 不单独成要素
- 作用：指示对 **已识别主要素** 扩大扩读范围（通常至整节/整章）
- 须写入该主要素的 `logic_trace`，并扩大 `evidence` 采集范围

**形态 D — 子维度批注（同一要素多条）**

```
监管方案设置：第三方监管
监管方案设置：章证照监管
```

- 同属一个 `element_name`
- 抽取时 **合并** 为一条 `situation`，按子维度分条列举

### 2.3 有批注 vs 无批注

| 场景 | 优先级 |
|------|--------|
| 存在批注版 docx 或 `docx_comments_index.json` | **批注口径 > 本 SOP 要素卡 > 正文字面** |
| 无批注 | **本 SOP 要素卡 > 正文字面**；同义标题按 §七 变体表检索 |

若批注与正文冲突：以批注口径理解要素边界，在 `situation` 中陈述正文事实，在 `gaps` 中说明冲突。

## 三、通用抽取流水线（六步）

智能体必须按顺序执行，不得跳过交叉校验。

```
Step1 全文结构化
  → Step2 加载要素清单
    → Step3 锚点定位
      → Step4 证据扩读
        → Step5 情况归纳
          → Step6 交叉校验与缺口标注
```

### Step1：全文结构化

1. 读取 docx 全文（或 `ocr_text` 对应 md，但 **条款精度优先 docx 原文**）。
2. 提取并记录：
   - 文档标题、债务人/项目名称、债权金额上限（若有）；
   - 章节树：一级标题（如「一、」「二、」）、二级编号（如「（1）」「6、」）、三级条目。
3. 输出内部结构索引 `section_index[]`：`{ level, number, title, start_offset, end_offset }`（实现方式不限）。

### Step2：加载要素清单

加载 §四 全部 **11 个主要素** 及子维度（监管四维度、违约处置多锚等）。按清单顺序逐项抽取，避免遗漏。

### Step3：锚点定位（精确 → 模糊 → 同义）

对每个要素，按该要素卡中的 **锚点词典** 依次检索：

1. **精确匹配**：锚点字符串与正文子串完全一致（忽略全角/半角括号差异）。
2. **模糊匹配**：锚点为核心片段（≥8 字）在正文中出现。
3. **同义标题匹配**：按 §七 变体表匹配章节标题。

记录：`anchor_hits[]` = `{ anchor_text, match_type, locator }`。  
若无任何命中：`confidence` 初判为 `low`，进入 Step4 时用 **全文关键词二次扫描**（见各要素卡）。

### Step4：证据扩读（四级边界）

以每个 `anchor_hit` 为入口，按 **扩读级别** 取证据（取满足业务所需的最小充分范围，必要时升级）：

| 级别 | 规则 | 典型场景 |
|------|------|----------|
| L1 锚点句 | 仅含锚点所在句/段 | 长句锚点（如信托设立句） |
| L2 同级编号块 | 从锚点所在 `（n）` / `n、` 起，至下一同级编号前 | `（1）金额` → 读本息相关各 `（n）` |
| L3 整节 | 从锚点所属二级标题至下一二级标题前 | `10、退出方式` 整节 |
| L4 整章 | 从章标题至下一章标题前 | `三、违约情况及处置` 全章 |

**元批注强制升级**：若存在 comment#64、#102 类范围指导，对「违约处置退出方式」至少扩读至 **L3 或 L4**。

每条 `evidence.quote` 必须来自扩读范围内的原文，不得拼接不同章节无关句。

### Step5：情况归纳

1. 根据要素卡中的 **应回答问题** 与 **必读字段**，从证据块中提取事实。
2. 使用要素卡 **归纳模板** 撰写 `situation`（完整句，中文）。
3. 同步填写 `logic_trace`：说明锚点、扩读级别、口径依据（批注 id）。
4. 判定 `confidence`：
   - `high`：必读字段齐全，数值/机制明确；
   - `medium`：机制清楚但缺少数值或部分子维度；
   - `low`：仅定性描述或锚点未命中仅靠关键词推测。

### Step6：交叉校验与缺口标注

必须执行 §五 的依赖校验。对缺失项写入 `gaps`。全部 11 要素完成后，执行 §六 质量门禁自检。

## 四、要素操作卡（11 张）

以下要素名称 **不得改写**，与信息收集表及批注保持一致。

---

### 要素 01：风险隔离措施

**业务定义**  
识别本项目如何通过信托、SPV、特殊目的载体等实现债权风险与原始债务人/集团其他风险的隔离。

**应回答的问题**

1. 是否设立财产权信托、资金信托或其他信托计划？
2. 信托/SPV 与项目公司、债权人之间的权利义务如何安排？
3. 是否存在「委托人」「唯一指令权人」等关键控制安排？

**必读字段**

- 隔离工具类型（如财产权信托）
- 标的债权金额上限或范围
- 关键主体（信托公司、SPV、项目公司）及角色
- 管理费或成本承担方（若有）

**锚点词典（精确 → 模糊 → 同义）**

| 优先级 | 锚点/关键词 |
|--------|-------------|
| P0 | `设立财产权信托`、`财产权信托`、`上述债权委托…信托` |
| P1 | `信托`、`委托人`、`唯一指令权` |
| P2 | `风险隔离`、`破产隔离`、`SPV`（若与信托在同段共现） |

**扩读规则**

- 命中 P0 长句锚点：**L1** 含该段；若后文还有信托结构细则，升至 **L2**（同一交易结构小节内所有 `（n）`）。
- 勿与「要素 04 风险隔离措施（SPV层面）」混淆：本条侧重 **信托/载体设立**，不侧重决策机制细则。

**归纳模板**

```
本项目通过[信托类型/载体名称]实现风险隔离：[信托公司]享有对[项目公司]不超过[金额]的标的债权；
[SPV/委托人]担任[角色]，[指令权/管理安排]。[其他关键安排]。
```

**批注口径（训练样本）**

- comment#45：设立了财产权信托计划 → 情况中须明确写出信托类型。

**正反例**

- ✅「设立了财产权信托，信托公司享有标的债权，SPV 为委托人及唯一指令权人。」
- ❌「出现 SPV 字样」→ 未说明是否信托隔离。

**依赖关系**

- 与要素 02「本息支付」中本金组成可能交叉（SPV 优先级对应部分）。
- 与要素 04 互补，勿合并为一条输出。

### 要素 02：本息支付情况

**业务定义**  
归纳债权的基本偿付要素：本金、利率、支付节奏、期限等。该要素中的 **约定利率/固定收益率** 在业务上作为要素 06「罚息倍数」的 **分母**。

**应回答的问题**

1. 本金金额（上限/组成）？
2. 利率形式（固定/浮动、年化表述）？
3. 付息/还本节奏？
4. 项目或债权期限？

**必读字段**

- `principal`：本金金额及组成说明
- `rate`：利率数值或确定方式（作罚息倍数分母）
- `payment_schedule`：支付节奏
- `tenor`：期限

**锚点词典**

| 优先级 | 锚点/关键词 |
|--------|-------------|
| P0 | `（1）金额`、`本金不高于`、`全部由…优先级…组成` |
| P1 | `利率`、`付息`、`还本`、`期限`、`支付节奏` |
| P2 | `借款合同`、`本息`、`收益` |

**扩读规则**

- 锚点 `（1）金额` 仅为入口：必须 **L2 扩读** 同一交易结构小节下所有与金额、利率、期限相关的 `（n）` 条目，直至信息齐全或下一一级标题。

**归纳模板**

```
本金[金额/上限]，[组成说明]；利率[数值/确定方式]，将作为违约后罚息倍数的分母；
付息/还本[节奏]；期限[年限/到期安排]。
```

**批注口径**

- comment#46：必须覆盖本金、利率、支付节奏、期限；利率即罚息倍数分母。

**正反例**

- ✅ 四项齐全，并点明利率与罚息倍数关系。
- ❌ 只写「本金 3.2 亿元」未写利率与节奏。

**依赖关系**

- → 要素 06：提供分母 `rate`；Step6 校验要素 06 是否引用同一利率口径。

### 要素 03：增信措施约定

**业务定义**  
识别抵押、质押、保证、担保、差额补足等增信安排，并 **主动排查** 是否存在还款承诺函类文件。

**应回答的问题**

1. 有哪些增信类型（抵押/担保/保证等）？
2. 押品或保证人是谁（若正文有）？
3. 是否存在 **还款承诺函**？

**必读字段**

- `credit_enhancement_types[]`：增信类型列表
- `has_repayment_commitment_letter`：`true` / `false` / `unknown`
- 关键主体与押品（若有）

**锚点词典**

| 优先级 | 锚点/关键词 |
|--------|-------------|
| P0 | `（5）增信措施：`、`增信措施` |
| P1 | `抵押`、`质押`、`担保`、`保证`、`差额` |
| P2 | `承诺函`、`还款承诺`（全文负向检索） |

**扩读规则**

- 自 `（5）增信措施：` **L2** 扩读至下一同级 `（n）` 或上一级标题。
- **全文检索**「承诺函」「还款承诺」：若增信小节未写，其他章节亦须查。

**归纳模板**

```
增信措施包括[类型枚举及简要对象]；[未见/已有]还款承诺函[若未见须明确写「未见还款承诺函」]。
```

**批注口径**

- comment#47：包含抵押、担保；**未有**还款承诺函 → `has_repayment_commitment_letter = false` 须在 situation 中写出。

**正反例**

- ✅「含抵押、担保；全文未见还款承诺函。」
- ❌「有增信」不列类型、不查承诺函。

**依赖关系**

- 无强依赖；与要素 08「其他还款来源」注意区分（还款来源≠增信）。

### 要素 04：风险隔离措施（SPV层面）

**业务定义**  
在 SPV 或其他隔离载体层面，识别 **实际决策权、控制权、指令权** 安排；项目可能存在 **多个 SPV**，须分别说明。

**应回答的问题**

1. SPV（或载体）对重大事项的决策机制是什么？
2. 我司或相关方是否具有控制权/唯一指令权？
3. 项目公司层面的决策机制是否与 SPV 层面不同？

**必读字段**

- `decision_mechanism_spv`：SPV 层决策机制摘要
- `decision_mechanism_project_co`：项目公司层决策机制（若有）
- `control_rights`：控制权/指令权归属
- `spv_count`：单一或多家 SPV

**锚点词典**

| 优先级 | 锚点/关键词 |
|--------|-------------|
| P0 | `6、决策机制`、`（五）决策机制` |
| P1 | `决策机制`、`指令权`、`控制权`、`一票否决`、`股东会` |
| P2 | `SPV`、`合伙人`、`委派` |

**扩读规则**

- **双锚必查**：`6、决策机制` 与 `（五）决策机制` 可能分属不同章节（SPV 层 vs 项目公司层），须 **分别 L2/L3 扩读** 后合并。
- 若正文提及多个 SPV，对每个 SPV 分别摘录再合并 situation。

**归纳模板**

```
SPV层面：[决策机制/控制权安排]；项目公司层面：[决策机制]（若材料分述）；
[共X个SPV，分别…]（若适用）。
```

**批注口径**

- comment#62：实际决策权、控制权，可能多个 SPV。
- comment#86：关于项目公司的决策机制。

**正反例**

- ✅ 分 SPV 层与项目公司层两段归纳。
- ❌ 只抄「决策机制」标题无内容。

**依赖关系**

- 与要素 01 互补；与要素 05「分配顺序」常在同章相邻，evidence 可不同但勿混淆 situation。

### 要素 05：SPV的分配顺序和清偿顺序

**业务定义**  
归纳受益权或份额的 **分配顺序**、**清偿顺序**、优先劣后结构。

**应回答的问题**

1. 优先级与劣后级如何划分？
2. 分配顺序与清偿顺序的具体条款？
3. 是否与特定 SPV 份额或信托受益权对应？

**必读字段**

- `distribution_order`：分配顺序
- `liquidation_order`：清偿顺序
- `priority_structure`：优先/劣后/中间级（若有）

**锚点词典**

| 优先级 | 锚点/关键词 |
|--------|-------------|
| P0 | `（2）分配顺序：`、`分配顺序` |
| P1 | `清偿顺序`、`优先`、`劣后`、`中间级` |
| P2 | `分配`、`清偿`、`受益权` |

**扩读规则**

- 自 `（2）分配顺序：` **L2** 扩读；若该节较短且后文仍有「清偿」，继续至相关条目结束。

**归纳模板**

```
分配顺序：[…]；清偿顺序：[…]；优先劣后结构：[…]。
```

**批注口径**

- comment#63：仅要素名，无冒号后摘要 → 完全依赖正文归纳。

**正反例**

- ✅ 明确谁先谁后、对应哪类份额。

## 五、复合要素与冲突处理

### 5.1 多锚聚合（要素 07）

1. 按 §四 要素 07 锚点表顺序 A→B→C→D 依次定位。
2. 合并 `evidence`，`situation` 单条输出。
3. `logic_trace` 列出各锚点扩读级别及合并逻辑。

### 5.2 同锚多要素（要素 06 与 07）

锚点 `（2）实质性违约` 同时服务：

- 要素 06：提取利率上浮/罚息 → 分子
- 要素 07：提取处置、转让、退出权 → `exit_methods`

**同一 quote 可出现在两条 evidence 中**，但 `situation` 必须拆分，不得合并。

### 5.3 材料缺失与定性材料

| 情形 | 处理 |
|------|------|
| 锚点未命中 | 全文 P1/P2 关键词二次扫描；仍无则 `confidence=low`，`gaps` 写「正文未见[要素]相关章节」 |
| 仅有定性无倍数 | `multiple` 填「无法从正文确定」，`gaps` 写「待补充明确倍数或罚息利率数值」 |
| 多来源数值不一致 | `situation` 陈述正文各处表述，`gaps` 写冲突及建议以何为准 |

### 5.4 非尽调报告材料

- PPT/可研：仅可作 **背景补充** 写入 `logic_trace` 末尾，**不得**作为 11 要素主 evidence。
- 合同附件未纳入当前 docx：在 `gaps` 标注「尽调报告引述但正文未展开，需原合同」。
